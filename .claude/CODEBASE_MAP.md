## Conventions
- **`bg-brand-gradient` sets `background-origin: border-box`** (2026-09-30): with the default padding-box origin, a bordered element (the `onDark` ButtonLink's transparent 1px border) repeated the gradient's end colour into the border as a light stripe on its left edge. Keep this if the utility is ever rewritten.
- **Button copy (user, 2026-09-30): at most 3 words per button label** ("Book a call", "Learn more", "Start a project", "View products", "Get started"…). Keep longer phrasing in headings or body copy, not in `cta` labels.
- **CTA sizing (user, 2026-09-29):** the booking CTA is labelled "Book a call" everywhere, and every one uses ButtonLink `md` (44px/15px), including section CTAs in SplitSection/FeatureGrid, the home hero and How we work. **Exception: the navbar's is `sm` (36px/14px)**; the user found `lg` (48px) and then `md` (44px) too big for the 72px bar (2026-09-30). `lg` was removed from ButtonLink. In-card buttons (Learn more, Discuss this) stay `sm`. Links: Problem cards → the matching `/products#…`, What-we-build cards → `/services#…`, "View all services"/"Explore our services" → `/services`. Footer `/privacy` and `/terms` still 404 (no legal pages exist).
- **Clickable cards (user, 2026-09-29):** a card with one button is wholly clickable and hover-linked. Use `ButtonLink stretched` (an empty `::after` covering the card) on a card that has `relative group/card`; the button's hover look then also fires on `group-hover/card`. It stays one focusable link, so never put a second link or button inside such a card. Applied to: home Problem cards, What-we-build cards, Services detail rows (with `first:/last:` rounding for the row hover tint), and Products cards (plain `Link` with the same `after:` layer). Not applied to: Challenges gap rows (text link, not a button), the Featured project card (its diagram scrolls sideways and an overlay would block it), or the How-we-work step panel (a tab panel, not a card).
- **Section width:** all content containers (Problem, Services heading, Workflow, Selected work, Technology, FAQ, footer) use **`max-w-[80rem]`** (1280px, which lines up exactly with the header bar `max-w-7xl`; user 2026-09-18, after an earlier widening to 88rem); the hero keeps its own narrower text column. Section eyebrows are a `text-sm font-medium text-brand-700` `<p>` above `SectionHeading` (`text-brand-300` on ink).
- **Section rhythm:** every page section (hero bottom, all `main > section`, footer top) uses **`py-16 sm:py-28`** vertical padding (phones were `py-24` until 2026-09-28; **exceptions: Technology uses `pt-16 sm:pt-20` and FAQ `pt-12 sm:pt-16`, so Featured project → FAQ is 112/176px (user, 2026-09-18); user request 2026-09-18: Problem has no top padding, so hero → Problem is the hero bottom padding alone, 64/112px**), so any two adjacent blocks are 128px apart on phones and 224px from `sm` up. Inner-page `PageHero` is `pt-32 sm:pt-44` with `pb-16 sm:pb-24`, or `pb-4 sm:pb-6` when it has a stat row (stats `mt-20`; user, 2026-09-29, two passes). **Responsive rule (user, 2026-09-28): desktop (`lg`, ≥1024px) is signed off and must not change; small-screen fixes go in base classes already overridden at `sm`/`lg`, or in `max-lg:`/`md:max-lg:` variants. Prove it with a layout dump (every rendered element's box/font/colour at 1024/1280/1500) diffed before vs after.** New sections must use the same padding; don't add margins between sections.

- **Animation performance rules (2026-09-18, after a measured fix):** infinite animations must be `transform`/`opacity` only. Never animate `background-position`, `left`/`top`, `box-shadow`, or a (registered) CSS variable: each of those ran style + layout 60×/s forever. **No `var()` inside transform keyframes** (it keeps the animation off the compositor; use literal keyframe variants like `comet`/`comet-right`). Never rotate a large masked box: a comet is `shared/ui/ring-comet.tsx` (a ~130×20px clipping window rotating about the ring centre). Don't wrap animated content in `mask-image`: fade with static white gradient overlays, and for rings concentric with a radial fade use a constant per-ring alpha (`ringFadeAlpha`). Keep iterations long (dashes 80px/8s, packets 4 passes per 12.8s), because React listens for `animationiteration` at the root and each event costs a main-thread frame. No `backdrop-blur` on the fixed header or over animated areas. Measure with a CDP probe (LayerTree + Performance.getMetrics) against `next start`. **Never put an infinitely animated child inside a `rounded-* overflow-hidden` container** (the old `.reveal` class is gone, but the rule stands): the rounded clip needs a mask layer, and on /about it pushed the page's comets onto the main thread (≈190 ms/s, 60 style recalcs/s, fixed 2026-09-28). Animate the rounded container itself (Stats, StackShowcase), or drop the parent clip and give rows their own background/rounding (GapRows, ServiceDetails, OpenRoles). Sector illustration keyframes: `scan-sweep` (12s). Packet tracks next to page edges go in an `overflow-hidden` (unrounded) wrapper so their translate can't widen the page. The same applies inside scroll containers: a packet track sliding past a leg's end counts as the scroller's overflow and makes its scrollbar flicker (fixed 2026-09-29 in `automation-flow.tsx`: the graph canvas is `overflow-hidden` and the frame is `overflow-x-auto overflow-y-hidden`). As a backstop `<body>` has `overflow-x-clip` (root layout; `clip`, not `hidden`, so the FAQ/Steps `lg:sticky` headings keep working).
